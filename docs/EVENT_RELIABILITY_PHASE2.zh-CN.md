# 第二轮可靠性专项修复

基于 PR #26，不新增事件处理、Skill 或打印机控制。
Shutdown 通知先持久化再查询，诊断原因仅在尚未分配路由时更新原消息，
否则保留本地记录。停机恢复独立关联，分发按同一故障因果顺序发送。
本地异常数据进入 dead_letters；远端故障仍按重试处理。
查询 ID 在连接内部隔离。

独立通信看门狗在重连等待时继续检查已确认的传输断线；
连接超时有界。数值规则需有新观测确认才完成持续窗口，
订阅刷新可确认未改变的字段。打印任务优先采用可选 history 的任务身份，
不可用时用打印时长与文件位置回退辅助识别；不能保证补齐断线期间所有任务。

filament_force 消费全部返回记录，游标和事件原子保存，
已知 boot 的序号缺口产生告警。首次观测建立基线，
无法证明监控开始前遗漏数量。保留源事件 ID。
源单调时钟与连接/ready 时钟域独立于 UTC 接收、生成和入队时间，
不伪造源绝对时间。

SQLite 增加部分索引，按小时压缩七天前已终结普通 G-code 载荷，
每批最多 500 条；保留事件 ID 和路由审计，不删除关键或待发送事件。
并非严格容量上限，SQLite 可复用空闲页但文件不一定缩小。
健康检查显示库大小、隔离计数和各路由待发状态。
实机仍需测试高负载、长期运行及真实通信故障。

执行 python -m pytest -q 与 ruff check .；压力测试覆盖 5000 条终结记录、
完整性及关键告警调度，不代表 Jetson 实测吞吐量。
