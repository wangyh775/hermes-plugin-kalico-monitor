# v0.2 零模型查询与统一安装

一个仓库，两个组件：Hermes 插件负责斜杠命令，独立 Kalico Monitor 负责 Moonraker WebSocket、SQLite 队列和 Webhook 推送。**不会**把长期监听循环运行在 Hermes Gateway 进程中。

## 零模型命令

- /kalico 或 /kalico status：打印状态、文件、进度、喷嘴与热床温度
- /kalico temp：温度与目标值
- /kalico alerts：最新 5 条告警和未投递数量（SQLite 只读）
- /kalico health：最近心跳和队列长度
- /kalico help：用法

Hermes 使用 ctx.register_command 直接路由上述命令，不进入 Agent 推理；自由文本仍会调用 Agent。Hermes Gateway 必须包含支持 platform/source 关键字上下文的版本（已在 2026 年 10 月的上游更新中提供）。**飞书真实机器人环境尚未验证**。

## 权限

必须设置 KALICO_ALLOWED_CHAT_IDS=oc_你的群聊ID，多个以英文逗号分隔。不设置时拒绝所有远程命令。白名单只控制 /kalico，Hermes 原生飞书渠道权限仍须配置。禁止通过命令输入任意 Moonraker URL 和数据库路径；只读命令不会发 G-code、控制运动或修改温度。

## 单机 Linux 安装（同一 Linux 用户）

~~~bash
git clone https://github.com/wangyh775/hermes-plugin-kalico-monitor.git
cd hermes-plugin-kalico-monitor
git switch feat/v0.2-fast-commands
bash scripts/setup-user-service.sh
nano ~/.config/kalico-monitor/monitor.env
hermes plugins install "file://$PWD" --enable
hermes plugins list
~~~

脚本只建立项目虚拟环境、配置模板和 systemd 用户服务，不会自动启动，不会覆盖已有 monitor.env，也不会修改 Hermes 配置。编辑 monitor.env 的 MOONRAKER_URL、HERMES_WEBHOOK_URL、HERMES_WEBHOOK_SECRET、KALICO_ALLOWED_CHAT_IDS、KALICO_MONITOR_DB。将 docs/hermes-webhook.example.yaml 内容合并到 ~/.hermes/config.yaml，切勿覆盖其他平台配置。Webhook secret 必须保持一致，密钥文件权限 600。

前台试运行（验证完按 Ctrl+C 退出）：

~~~bash
set -a
source ~/.config/kalico-monitor/monitor.env
set +a
.venv/bin/python -m kalico_monitor.monitor
~~~

随后按需启用后台服务：

~~~bash
systemctl --user enable --now kalico-monitor
systemctl --user status kalico-monitor
journalctl --user -u kalico-monitor -f
# 需要用户注销后仍运行时：
sudo loginctl enable-linger "$USER"
~~~

不要同时运行前台和后台监听，以免重复监控；不应同时启用旧的 Cron 告警。Hermes 插件和监控服务需共享数据库路径和配置文件；不同用户部署必须分别配置权限和路径。完整的 Hermes 飞书机器人接入、WebHook 配置要依安装版本验证。

## 管理

~~~bash
systemctl --user start kalico-monitor
systemctl --user restart kalico-monitor
systemctl --user stop kalico-monitor
systemctl --user disable --now kalico-monitor
.venv/bin/python -m pytest -q
hermes plugins validate kalico-monitor
~~~

health 心跳只证明监控进程还在运行，并不证明 Moonraker 或飞书告警送达。整机断电时同机 Hermes 与 Monitor 都无法告警。高温打印机应有独立于本软件的过温断电和急停机制。

本 v0.2 是开发版本：先合并 PR #2（Ruff/故障测试），再合并本版后续 PR。

## 打印状态定时报告

在 `~/.config/kalico-monitor/monitor.env` 设置 `KALICO_PROGRESS_REPORT_MINUTES=30`，即每 30 分钟发送一次打印进度摘要；`0` 为关闭（默认），允许 5–1440 分钟。设置完成后执行 `systemctl --user restart kalico-monitor`，无需另设 Cron。自动事件故障告警仍然按原来的事件触发逻辑运行。

报告使用已有 Hermes Webhook，`deliver_only: true`，**无需 LLM 推理**。仅在打印中、Klippy ready 且状态数据新鲜时生成；暂停、关机、连接失败时停止计时，恢复打印后重新计时；完成和取消不再发送状态摘要。报告内容包括打印文件、按文件位置估算的进度、已打印时间、喷嘴/热床实际及目标温度、能读到时的层数；不对打印质量做没有依据的判断。

重启进程时，下一次报告时间与序号从 SQLite 恢复。定时报告和普通故障告警共用有重试机制的持久化队列，服务端故障期间可能积累旧报告；恢复后补发的消息代表历史状态，须通过 `/kalico status` 核查最新数据。

## 自定义喷嘴力回弹事件（Kalico PR #13）

本功能是 **可选、只读** 的监控桥接。Kalico PR #13 的
\`[nozzle_force_monitor]\` 负责分析称重传感器回弹事件、判定疑似堵头，并按自身配置决定是否运行 PAUSE。
Hermes 和 Kalico Monitor **不会发送 G-code 或控制打印机**。

### 开启

1. 在 Kalico 中安装并验证 [PR #13](https://github.com/wangyh775/kalico/pull/13)，
   在 \`printer.cfg\` 配置 \`[nozzle_force_monitor]\`，先使用 \`action: log\` 完成标定。
   自动暂停仅在经过实机验证后才考虑设置 \`action: pause\`。
2. 通过 Moonraker 查询 \`/printer/objects/query\`，确认 \`nozzle_force_monitor\` 状态对象存在。
3. 在 Monitor 的 \`monitor.env\` 增加：
   \`\`\`ini
   KALICO_WATCH_NOZZLE_FORCE=1
   \`\`\`
   默认值为 \`0\`，即关闭。重启 Monitor systemd 服务以应用配置。
4. 在已授权的飞书聊天发送 \`/kalico force\`，不调用 LLM，查询当前喷嘴力、
   基线、偏差、回弹匹配数、阈值、窗口、锁存状态和动作模式。

### 告警触发和去重

Monitor 通过 Moonraker WebSocket 订阅 \`nozzle_force_monitor\`，观察
\`triggered\` 和 \`trigger_count\`，识别新触发并生成
\`nozzle_force_anomaly\` 告警。告警附带打印文件、层数、匹配事件数、
\`window_s\`、力阈值和触发时偏差。该异常只能表明**疑似堵头或其他喷嘴力异常**，
不是堵头确诊；也不会在缺少证据时声称 PAUSE 成功。

每个新事件的通知序号和检查点通过 SQLite 原子持久化；Monitor 进程重启、
Moonraker WebSocket 重连不会为相同的锁存事件重复入队。
若同一时刻或紧接着因 \`action: pause\` 出现普通打印暂停通知，
在同一打印任务的短窗口内优先显示专门的力异常告警，避免刷屏。
独立手动暂停仍正常通知。

如果当前 Kalico 没有加载此可选对象，Monitor 会自动退回原有状态订阅，
不影响正常打印、温度和故障告警；\`/kalico force\` 会提示对象不可用。
该功能只适配 PR #13 的 **时间窗口相似回弹判定**，不是旧版持续超阈值算法。

### 重要限制

- **不能直接把 Klippy 内部的 \`printer.send_event\` 当成 Moonraker 外部事件。**
  当前桥接依赖 \`get_status()\` 状态订阅。
- 通知消息进入已有 Hermes 签名 Webhook 和 SQLite 重试队列；
  Hermes \`deliver_only\` 可零 LLM 投递飞书。
- Klippy 重启、配置重载、监控器重启时，检查点依赖持久化的计数与锁存状态；
  后续建议在 Kalico 侧增加独立 \`last_trigger_id\` / 时间戳，
  使跨 Klippy 重启和重放场景具备更严格的事件身份。
- PR #13 目前仍是 Draft；此集成必须在真实 Kalico、Moonraker、
  Hermes Gateway 和飞书环境下进行端到端验证。
- 既有硬件急停、独立过温保护不受本功能替代。
